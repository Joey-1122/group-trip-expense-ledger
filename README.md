# 多人旅行，一人管账

给 AI Agent 用的多人旅行记账分账 Skill：一名旅行成员负责报账，Agent 创建可直接查看的账本，并持续处理记录、AA 分摊、外币、改账、查账和最终结算。跨宿主可用（OpenClaw 飞书/微信、Coze、WorkBuddy 等）。

## 开始使用

1. 把本仓库交给支持 Skill 的 Agent，让它读取 `SKILL.md`。
2. 首次启用时 Agent 会先说明：会按你所在平台推荐一个手机电脑都能打开的账本、由你确认；每笔记录都会同步，记错也能改或撤销。
3. 对 Agent 说：

   > 我要去韩国旅行，帮我记账。

4. Agent 逐步引导：确认同行人 → 判断从哪到哪（国内/国际）→ 按当前平台能力**推荐一个账本方案让你选**（不甩技术菜单）→ 国际行才问外币现金/交通卡准备。
5. 建好后给出账本链接，并教四个动作：记一笔、看账、改错、问谁欠谁，然后邀请第一笔。
6. 以后自然语言报账：

   - `A 付了 30000 韩元吃饭，四个人 AA。`
   - `刚才那笔改成只有我和 A。`
   - `我一个人餐饮花了多少？`
   - `现在谁欠谁？`

## 设计要点

**六条正向不变量**（从设计上避免真实踩过的坑，而不是堆"小心 X"）：

1. 写入前一行回显、写入后一行回执 —— 防相邻消息串账、记错对象。
2. 没有新消费事实的消息 = 提问只回数字、绝不写库；改账必须指向某条已有记录 —— 防把查账当改账。
3. 已入账本币金额默认锁定；只有"待出账"状态才接受更新 —— 防把算好的汇率又改一遍。
4. 回执自带重复提示 —— 防重复入账。
5. 账本自己持有规则（默认参与人、吃喝默认共同等写进可见设置）—— 防规则靠记忆出错。
6. trip profile 决定加载哪些模块：国内行只用单币种模型，国际行才加载外币模块 —— 复杂度不下放给所有人。

**跨平台落地**：按当前宿主真实能力推荐账本方案 + 用户选择，飞书多维表格 / Coze 表格 / 通用在线表各有具体落地路径与降级链，不止抽象 contract。

**外币按需**：国际行才加载 `references/foreign-money.md`，内含加权成本资金池、免密钥实时汇率接口、目的地储值卡（Suica/八达通/T-money 等）对照表。

## V1 范围

一趟当前旅行；一个人替所有同行人记账；AA / 个人 / 请客 / 各付各 / 自定义金额；外币现金、交通/储值卡、信用卡或线上换算；自然语言改账、撤销、统计、结算。不处理多人同时编辑、并行旅行、退款、复杂账单 OCR。

## 文件结构

- `SKILL.md`：核心 —— 六条不变量、钱的定义、onboarding（含载体能力推荐）、日常记账/改账/查账/结算、国内分摊与结算算法。
- `references/foreign-money.md`：仅国际行加载 —— 钱包/资金池、实时汇率接口、目的地支付方式对照表。
- `references/examples.md`：真实用法对话示例（不确定时读）。
- `scripts/trip_ledger.py`：可选的确定性分摊/结算校验；无脚本宿主可按 SKILL.md 中的 prose 算法手算。
